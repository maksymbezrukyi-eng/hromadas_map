# Промт: оновити hromadas_map з нової версії воркбука

Вставте цей текст у новий чат Claude Code, відкритий у папці
`hromadas_map` (`C:\Users\bezrma\Desktop\Claude code\hromadas_map-main`),
коли з'явилась нова/оновлена версія
`Турбота_Workbook_Відбір_громад_динамічний_скоринг_v5.xlsx`. Вкажіть шлях
до файлу замість `<ШЛЯХ_ДО_WORKBOOK>`.

---

Онови дані інструмента hromadas_map з нової версії Excel-воркбука.
Це рутинна операція оновлення даних, не зміна коду. Виконай так:

1. Переконайся, що файл `<ШЛЯХ_ДО_WORKBOOK>` не відкритий в Excel
   (скрипт читає його напряму, відкритий файл може бути заблокований).

2. З кореня репозиторію запусти:
   ```
   .\scripts\convert_workbook.ps1 -WorkbookPath "<ШЛЯХ_ДО_WORKBOOK>"
   ```
   Це перезапише лише `data/id_mapping.json` і `data/hromadas_survey.json`.
   Нічого іншого в репозиторії конвертер не чіпає.

3. Перевір вивід скрипта:
   - Скільки громад зведено / не зведено в `id_mapping.json`. Відомі й
     очікувані "не зведено" — 4 громади (Близнюківська, Березівська з боку
     воркбука; Мерефянська, Болградська з боку інструмента — розбіжність
     складу з `data/hromadas_68.geojson`, задокументована в CLAUDE.md як
     Відома проблема №2). Якщо з'явилась ЯКАСЬ ІНША незведена громада —
     зупинись і повідом мені, замість того щоб пушити далі: значить назва
     в новому рядку воркбука не збігається з тим, що є в `js/data.js`
     (`H[].n`/`H[].o`), і потрібне ручне зведення.
   - Скільки громад тепер із балом опитування / реальними даними
     "діти до 1 року" — щоб на око оцінити, чи справді додались нові дані,
     а не 0.

4. Подивись `git diff --stat data/id_mapping.json data/hromadas_survey.json`
   і побіжно `git diff data/hromadas_survey.json` — переконайся, що зміни
   виглядають осмислено (не всі числа занулились, не зникли громади).

5. Якщо все ок — закомить і запуш:
   ```
   git add data/id_mapping.json data/hromadas_survey.json
   git commit -m "Update survey data from workbook (<коротко що змінилось>)"
   git push origin master:main
   ```
   Локальна гілка називається `master`, віддалена — `main`; саме тому push
   явно вказує `master:main`, а не просто `git push`.

6. Скажи мені: скільки громад оновлено, чи були нові "не зведено", і що
   GitHub Pages підхопить зміну протягом ~5 хвилин (кешування).

Обмеження, яких треба дотримуватись (не питай дозволу, просто дотримуйся):
- НЕ чіпай `data/hromadas_68.geojson` — розбіжність складу громад
  виправляється окремим рішенням, не в межах цього оновлення.
- НЕ редагуй `js/*.js` чи `index.html` для рутинного оновлення даних —
  тільки два JSON-файли.
- НЕ використовуй `git push --force` і не переписуй історію.
- Якщо `.gitignore`/структура репозиторію виглядає інакше, ніж очікується
  (наприклад скрипта нема за вказаним шляхом) — зупинись і спитай, а не
  вигадуй заміну.
